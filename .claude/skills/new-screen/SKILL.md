# Add the screen $ARGUMENTS

A screen is a vertical slice through every layer, and each layer has a rule (CLAUDE.md, Critical Rules). Do the steps **in this order**, run the gate after step 9, and ask the user before inventing anything an IAM service or the shell has not defined (an endpoint, a permission, a role).

1. **Read the contract.** The IAM service's Swagger copy in `test/contract/swagger/` (add it with `npm run contracts:pin` after reading the diff if the service is new) and the screen spec/LLD section. Decide: the operations (list, get, create, update, delete), the `recordVersion` each write needs, the permission that opens it, and whether it needs read-only handling or step-up. If the endpoint or permission does not exist, stop and report that.
2. **Metrics first.** The screen's data load is a `resource` label with a closed value set: add it to `LOAD_RESOURCES`, and each write to `ADMIN_ACTIONS` (`src/domain/events/admin-events.ts`), and add the row(s) to `docs/observability/metrics.md` so the inventory matches (`test/unit/metrics` fails otherwise).
3. **Scaffold:** `node .claude/skills/new-screen/scripts/scaffold.mjs <PascalName> --prefix <keyprefix> --resource <resource>`. It writes `src/presentation/pages/<Name>Page.tsx`, `src/presentation/features/<prefix>/use<Name>.ts`, `src/infrastructure/configuration/locales/en/<prefix>.json` and `test/unit/pages/<prefix>-page.test.tsx`, refuses to overwrite, and checks the resource exists. The generated hook returns `[]` until step 4 replaces it.
4. **The data path, inside out:**
   - `src/domain/entities/<x>.ts` (readonly interfaces, IDs and `recordVersion`), `src/domain/repositories/<X>Port.ts` (one method per operation, `signal?` last), rules in `src/domain/rules/admin-rules.ts` for what the UI checks before a write (pure; every `src/domain/` file stays above 90%, both paths of each rule tested);
   - `src/infrastructure/api/<x>.ts` (the adapter on `scope.client`, `requireTenant(scope)` for tenant paths, `withSignal`) and its mapper in `mappers.ts` (snake_case JSON ⇄ domain; the Swagger's names, never invented ones);
   - `src/application/use-cases/<Op>UseCase.ts` (one per port operation: copy an existing one), then `createUseCases` and `AdminRepositories` in `use-cases/index.ts`;
   - the port joins `AdminServices` (`presentation/features/services.tsx`), `useAdminUseCases`, `app/providers/composition.ts`, and `test/fixtures/services.tsx` (`unwired('<x>')`); `test/unit/infrastructure/composition.test.tsx` lists the service keys.
   - the feature hook calls `useCases.<op>.execute()` through `useTrackedQuery` / `useTrackedMutation` (`action:` from `ADMIN_ACTIONS`, `invalidate:` the keys the write makes stale); add the query key to `src/application/queries/keys.ts`.
5. **The page:** fill in the scaffold with the dashboard's look: `components/styles.ts` (`card`, `table`, `th`, `td`, `btnPrimary`, `btnOutline`, `input`), `identity/` pills and avatars, `Dialog` / `Drawer` / `ConfirmDialog` / `ConflictDialog`, the SDK's `formatDate` / `formatNumber`. Every state is visible: loading, failed (`LoadFailed`, never a blank page), empty, read-only (disabled with the reason), 409 (`ConflictDialog` Reload). Names come from User Profile through `useUserProfiles`, never a raw ID.
6. **Words:** keep the locale file's keys prefixed by `<prefix>.`; import it in `src/infrastructure/configuration/messages.ts` (add to the `en` spread) and add its prefix to the `extra`-prefix handling in `test/unit/i18n/catalog.test.ts` only if some keys use another prefix. Every key must be used as a literal `t('…')`.
7. **Route and access:** a `<Route>` in `src/app/routes/index.tsx` inside `Section` (`template="/t/:slug/admin/<path>"`, a `TITLES` entry), the section in `AdminSection` and `sections` in `src/presentation/features/access/useAdminAccess.ts` with the permission from step 1, and `test/unit/authz/admin-access.test.tsx`.
8. **The shell's sub-menu is web-shell's** (`app.frame.admin.*` in `../web-shell/src/app/routes/App.tsx`, with its own permission rule). Do **not** edit it from here (`guard.sh` blocks it): write a short handoff in `docs/lld/` naming the label, the path `/admin/<path>` and the permission hint, and tell the user.
9. **Tests:** fill in `test/unit/pages/<prefix>-page.test.tsx` (the states in the scaffold's TODO), a contract case in `test/contract/adapters.contract.test.ts` through the real client, an e2e flow if the screen changes state (`test/e2e/admin-flows.test.tsx`, the fake IAM in `test/fixtures/fakeIamCore.ts` gets the routes in the Swagger's shape, and sample data in `dev/mock-iam/sampleData.ts` so the harness shows it), the screen in `test/unit/a11y/screens.test.tsx` (axe), and a `<prefix>-design.test.tsx` for the look. Keep accessible names stable.
10. **Gate:** `/gate full`. Then docs in the same change: the LLD (screen table, §7 flow), `ARCHITECTURE.md` if a layer changed, `docs/lld/mfe-admin-lld.md` open items, and a `CHANGELOG.md` `[Unreleased]` line. Review with the `invariant-reviewer` and `doc-sync-reviewer` subagents on the diff.

Report to the user: what was built, the endpoints used, the permission chosen, what the shell must add (step 8), and anything left as a TODO.

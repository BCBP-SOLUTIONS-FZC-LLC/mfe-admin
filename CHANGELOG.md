# Changelog

All notable changes to this remote are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and versions follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html) as [VERSIONING.md](VERSIONING.md) applies it to the runtime contract: the container, `./App`, shared modules, routes, permissions, `runtime.json`, image paths, metrics.

**How releases map to this file:**
- Each Git tag `vX.Y.Z` has a dated `## [X.Y.Z] - YYYY-MM-DD` section. `release.yml` refuses a tag without one and uses its text as the GitHub Release notes.
- `package.json` `version` matches the latest section.
- A pull request that changes `src/`, dependencies, the `Dockerfile`, `nginx/`, `rsbuild.config.ts` or `index.html` adds a line under `[Unreleased]` (`changelog-check.yml`).
- Released sections are not edited.

### Added (2026-11-25 — composition root and services)

- **Telemetry:** `src/infrastructure/telemetry/metrics.ts` records the five Tier 3 `iam_admin_*` metrics through the SDK's `/metrics`, behind the `AdminTelemetry` port; `createMetricsTelemetry(clock)` takes a clock so timing is testable. `docs/observability/metrics.md` now lists full label sets in every row, and `test/unit/metrics` checks the definitions against the SDK registry, the standard and that page.
- **Errors:** `infrastructure/api/problem.ts` maps a failed call to a metric outcome (`failure` for any 4xx, `error` for 5xx, network and timeout; an abort is neither), a retry rule for queries, a catalogue message key for each known `errorCode` (including every gateway deny code the SDK lists), and reads `record_version` from a lock conflict. The catalogue has the matching `errors.*` messages.
- **Server state:** one TanStack Query `QueryClient` per mount (`app/providers`), cleared on unmount; queries retry network errors, timeouts, `429` and `5xx` twice, mutations never; no refetch on window focus. Query keys, workspace slug first, are in `application/queries/keys.ts` (ADR 0001 updated: it first said `infrastructure/api`). arch-lint now allows TanStack Query in `app/` and `presentation/features/` only.
- **`userBatcher`:** de-duplicates and chunks `POST /users:batch` at 200 IDs, one call after another; stateless, the 60 s freshness is the Query cache's `staleTime` (`USER_STALE_MS`).
- **Access:** `useAdminAccess` turns the eight permissions and read-only state into hints; the section nav lists only sections the user may open, and a section they may not open shows "You don't have access to this section." instead of redirecting.

### Added (2026-11-25 — IAM adapters and contract tests)

- **Adapters** (`infrastructure/api`): `orgMembership`, `userProfile`, `catalog`, `groupMapping`, `audit` and `delegationPolicy`, each a port on the SDK `ApiClient` with `/v1/…` route templates whose parameter names match the Swagger's. `mappers.ts` and `readers.ts` turn service JSON into domain types: a missing or mistyped field is a `MappingError`, a list sent as `null` is empty, a role code the UI does not know is dropped, `invitation_id` is read and the legacy `id` never is. Nothing is sent without a workspace (`MissingWorkspaceError`).
- **Composition:** `createAdminServices` wires all six adapters and the telemetry; `AdminProviders` gives them the session context's tenant ID; the ApiClient is made on first use.
- **Contract tests** (`test/contract`, `npm run test:contract`): every adapter method runs through the real SDK client against a vendored copy of the six IAM Swagger files, pinned by SHA-256 (`PIN.json`; `npm run contracts:check` and `contracts:pin`). 45 cases check the request (method, path, declared query, body with no unknown field), the fixture as a valid answer, and the mapped result; error answers and the Swagger's known gaps have their own tests. New dev dependencies: `yaml`, `ajv`.
- **Ports** now return what the services answer: `DepartmentVersion` (P-24, P-25), `MemberStatusChange` (P-7), `RolesChange` (P-28).
- **Audit search** takes one entry type (`planAuditQuery` refuses more: `one-entry-type-only`) because the SDK cannot repeat a query key; exports take several. See [docs/lld/sdk-api-client-handoff.md](docs/lld/sdk-api-client-handoff.md).
- **Tests:** the layer rules accept `.roles` in a spread or a string; the SDK-rule test no longer flags `...roles`.

### Added (2026-11-25 — E2 User detail and E2a step 2)

### Added (2026-11-25 — E5 Group mappings)

- **E5** (`pages/GroupMappingsPage.tsx`, `mappings/`): which department, level and role an identity-provider group grants at SSO sign-in. **Plan gate** from P-1 (never a role): a trial workspace is told "SSO is available after you upgrade", a Starter workspace gets an upgrade card, and neither asks the service for the mappings. **Groups to departments:** one row per group, joined from the department and level lists (a group in only one list keeps a half-set row, with a note that a group needs both); saving writes the two lists, departments then levels, and if the second fails after the first went through the page says which part saved and **Retry the rest** sends only the second. **Groups to roles:** its own write. Names are trimmed, an omitted row is deleted, an empty list is written when every row is removed. Refusals before sending: a missing or duplicate group name, a name over 255 bytes. The service's answers in plain words: `MAPPING_CONFLICT` (someone else is saving), `DEPARTMENT_NOT_IN_CATALOG`, `ROLE_ASSIGNMENT_FORBIDDEN` (only an owner can change owner mappings), `503`; a lost lock race offers Reload. The page says mappings only add access and apply at each person's next SSO sign-in.
- **Owner rows:** an admin sees them locked, is not offered the owner role, and can save the other rows beside them; `planGroupMappings` now takes the lists as the service has them, so a non-owner is refused only for changing an owner row (it used to refuse any draft that contained one).
- **Shared plumbing:** `useGroupMappings` (asked only when the plan allows), `useSaveDepartmentMappings` (the two writes and the half-saved state), `useSaveTenantRoleMappings`.

### Fixed (2026-11-25, hardening)

- **A "saved" notice could be lost when a save settled after its card had remounted.** A callback passed to `mutate` is skipped for an unmounted component; the six cards keyed by a record's version (profile, roles, role label, workspace settings, delegation policy, both mapping tables) now use `mutateAsync(...).then(...)`. It passed in the unit tests only by timing.
- **Empty table headers** on the actions column of four tables now say "Actions" to a screen reader.
- **Two fields had the same accessible name** ("Group name 1" in both mapping tables); the role table's is now "Group name for role".
- **The "not permitted" view had no level-one heading**; it now keeps the section's title as an `h1`.
